# 常见问题

## Q1：apktool 回包报 `Invalid file` / 解析失败

apktool 版本过低。升级到 2.9+ 并使用与目标 APK 匹配的 framework：

```bash
apktool d -f -r app.apk -o decoded
apktool b decoded -o out.apk
```

`-r` 保留原始资源目录，跳过资源重新编译，能绕开大部分 aapt2 兼容问题。

## Q2：安装后提示「应用未安装」

未签名或签名与原应用不一致。必须用 `apksigner` 重新签名后才能装。

## Q3：剥离后应用闪退

大概率是完整性校验（签名校验 / dex 校验 / 资源 MD5 校验）。处理顺序：

1. 只用 `--confidence high` 重试，减少误删。
2. 定位崩溃日志：`adb logcat -s AndroidRuntime`。
3. 找到校验点后，在 smali 里把校验分支改成 `return-void`。

## Q4：`pm disable-user` 禁用广告包后系统卡在桌面

某些系统组件本身带 `ad` 字样被误禁。恢复：

```bash
pm enable <包名>
```

或直接卸载模块重启。

## Q5：只屏蔽了域名，应用内广告还在

广告可能由以下渠道下发，域名屏蔽覆盖不到：

- 应用内置资源里的图片/视频广告位（需剥离）
- WebView 加载的本地 HTML 广告（需改 smali 里的加载 URL）
- 服务端下发的插屏配置（需抓包定位接口）

## Q6：怎么确认模块生效

```bash
# 检查 hosts
cat /data/adblock/hosts

# 检查被禁用的包
pm list packages -d | grep -i ad

# 观察日志
logcat | grep -i vivo_ad
```

## Q7：能否在非 root 设备上用

`tools/apk_ad_strip.py` 不需要 root，它是离线重打包 APK 的方式；Magisk 模块部分则需要 root。

## Q8：识别规则会不会误伤

规则分两档。默认只移除高置信度项。命中弱关键词（如只有 `ad` 两个字母）的类会被标为「待确认」，需要显式加 `--confidence medium` 才会被删除。
